# دیباچه

سیستم آفلاین مدیریت یادگیری: برنامهٔ روزانه، پیگیری پیشرفت و مرور به روش لایتنر.
مشخصات کامل در [PROJECT_SPEC.md](PROJECT_SPEC.md) است.

## نصب (فقط یک بار، با اینترنت)

در Terminal داخل پوشهٔ پروژه:

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

پوشهٔ `.venv` یک محیط پایتون جدا برای همین پروژه است تا کتابخانه‌ها با بقیهٔ Mac قاطی نشوند.

## اجرا

روی `start.command` دوبار کلیک کنید. یا در Terminal:

```bash
.venv/bin/python app.py
```

بعد در مرورگر به `http://127.0.0.1:5000` بروید.

## اجرای تست‌ها

```bash
.venv/bin/python -m pytest
```

## داده‌ها و backup

- همهٔ داده‌های برنامه در فایل `data/dibacheh.sqlite3` است. خود منابع (نوت، PDF) سر جای خودشان می‌مانند.
- هر روز، اولین باری که برنامه باز می‌شود، یک کپی در `data/backups/` ساخته می‌شود، با نامی مثل `dibacheh-2026-11-05.sqlite3`.
- ۳۰ نسخهٔ آخر نگه داشته می‌شود و نسخه‌های قدیمی‌تر خودکار پاک می‌شوند. فایل‌های دیگرِ آن پوشه دست نمی‌خورند.
- پوشهٔ `data/` وارد Git و GitHub نمی‌شود.

**برگرداندن یک backup:**

1. برنامه را ببندید (پنجرهٔ Terminal آن را ببندید).
2. فایل `data/dibacheh.sqlite3` را برای احتیاط به جای دیگری منتقل کنید.
3. فایل backup دلخواه را در `data/` کپی کنید و نامش را `dibacheh.sqlite3` بگذارید.
4. برنامه را دوباره باز کنید.

**اگر ساختار جدول‌ها را تغییر دادید:** یک مورد جدید به انتهای فهرست `MIGRATIONS` در `database.py` اضافه کنید و موارد قبلی را عوض نکنید. برنامه موقع باز شدن فقط migrationهای تازه را اجرا می‌کند و داده‌ها می‌مانند.

## ساختار پوشه‌ها

| فایل یا پوشه | کار |
|---|---|
| `app.py` | سرور و مسیرها |
| `scheduler.py` | موتور چینش برنامه، بدون وابستگی به Flask یا SQLite |
| `leitner.py` | قانون‌های جعبه و مرور |
| `database.py` | کار با SQLite |
| `sources.py` | خواندن منابع، Browse و باز کردن فایل |
| `exporter.py` | ساخت خروجی HTML |
| `templates/` | صفحه‌ها |
| `static/` | CSS و JavaScript |
| `static/vendor/` | کتابخانه‌های محلی (بدون CDN) |
| `tests/` | تست‌ها |
| `data/` | دیتابیس و backup؛ وارد Git نمی‌شود |
